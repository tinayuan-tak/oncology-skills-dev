How to read this dashboard — glossary

Skill health: production_ready ready_unproven partial placeholder broken_or_drift

Card health: live wired partial blocked placeholder broken self_produced

broken = no path to data (no reader + no backing method, never fires); blocked = no live reader (honest gap); partial = reader exists but hasn't fired in a real package yet; live = has fired (passed/warned) in a real evidence package; orphan = card defined on disk but consumed by no skill (unclaimed measurement).

Drift severity — severity is about IMPACT, not badness

error (breaks verdict) warn (fix, non-breaking) info (roadmap, not a defect)

error = breaks the skill's verdict — declared status contradicts what's on disk (forces broken_or_drift); warn = a real gap to fix, but it does NOT break the verdict; info = not a defect — a roadmap/coverage signal (something true and worth surfacing; no one did anything wrong). Only error + warn appear in the Fix-next queue; info items are shown for transparency.

Drift codes — what each one means

  • error SKILL.md points at an entrypoint file that doesn’t exist skillmd_cites_nonexistent_entrypoint
  • error declared “wired” but a card it needs is broken status_wired_card_broken
  • error declared “wired” but has no runnable entrypoint status_wired_no_entrypoint
  • warn card references a dataset that isn’t registered in the data-catalog dataset_ref_not_in_catalog
  • warn SKILL.md’s card list disagrees with what run.py actually loads declared_cards_mismatch_runpy
  • warn composed skill fans out to a different number of sub-skills than declared fanout_count_mismatch
  • warn SKILL.md has no machine-readable status: field missing_status_field
  • warn card’s declared modality_relevance is outside its type’s routing set (P4) modality_relevance_drift
  • warn card routes to a modality-fit gate but declares no modality_relevance (P4) modality_relevance_missing
  • info RETIRED flag (2026-09-11): asserted a card in no dashboard_spec “can never fire”, which was false — the emission path reads cards_used, not a spec card_consumed_but_no_spec
  • info card is wired but has never fired in a real evidence package yet card_registered_never_fires
  • info card’s method label differs from the method the dispatcher actually imports stale_method_label

Modality routing (roadmap term “P4”)

P4 = the roadmap’s modality-vector layer: each card declares modality_relevance — which drug modalities (small-molecule, degrader, ADC, TCE, antibody) its evidence informs — so its signal routes to the right modality-fit gate instead of being stranded on the biology axis. This lens is metadata PARALLEL to health; it never changes a card’s health.

declared not_required missing drift
